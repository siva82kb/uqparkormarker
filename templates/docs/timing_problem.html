The clips are to be lined up with the sensor data using those times, so they have to be right. Some are not. This page shows why. {% endblock %} {% block body %}

What should happen, and what does

Each frame should be saved with the time it was filmed.

The recording program does not quite do that. It saves the time at which it got round to saving the frame.

Most of the time the two are the same to within a few hundredths of a second. But now and then the program is held up, for a moment or for several seconds. Then the two come apart.

How the recording program works

An everyday picture. A wall clock and a pile of letters.

Letters arrive one every minute. A clerk stamps each letter with the time on the wall clock and files it. If the clerk steps out for ten minutes, ten letters pile up. Back at the desk, the clerk stamps them all quickly, with the time on the clock now. The first letter in the pile gets a time ten minutes late. Two letters stamped within the same minute get the same time.

So a timestamp is never early. It can be late, by as much as the time the frame waited.

What a late stretch looks like

A late stretch always has the same three parts.

  1. A gap. Two neighbouring frames whose timestamps are far apart, for example 3 seconds instead of 1/30 of a second. This is when the program was held up.
  2. A catch-up. The waiting frames are saved in a rush. Their timestamps are bunched together and late. The program saves faster than the camera films, so now and then two frames in a row get exactly the same timestamp.
  3. Back to normal. Once no frames are waiting, the timestamps are right again.

The pictures themselves are fine throughout. Only the saved times are wrong.

Why it matters

A clip is {{ clip_seconds }} s long. Arm movements change within a fraction of a second. If a clip's time is wrong by a second or more, it will be matched to the wrong piece of sensor data, and nothing in the result will show that it happened.

In five of the six participants checked, the worst timestamps were between 2 and 11 seconds late.

A second, smaller problem

One idea is to ignore the timestamps and count frames instead: frame 900 is 30 seconds in, at 30 frames a second.

That does not work over long stretches. In every session there are a few seconds for which no frames exist at all (between 0.6 and 17.7 s per session). Counting frames from the start would drift by those seconds. So the timestamps are still needed. They only have to be used with care.

What is known and what is assumed

  • Known. The published recording program saves times in the way shown above. The gap, catch-up and repeated timestamps are seen in the recordings of all six participants checked.
  • Known. Test recordings from 2022 made at 10 frames a second show almost none of this. At 30 frames a second the program has a third of the time for each frame, so it falls behind more easily.
  • Assumed. The study used a changed version of the program, at 30 frames a second. It has not been confirmed that this version saves times in the same way.
  • Not known. Why some sessions have hold-ups of many seconds. The frame rate explains the scattered repeated timestamps, but not these.
